# Научная проверка утверждений

Проект ищет научные публикации по утверждению, выделяет подтверждающие предложения из аннотаций и определяет, поддерживают ли эти предложения утверждение или противоречат ему.

Последовательность обработки:

```text
Утверждение → Поиск публикаций → Выбор предложений → Вердикт
```

Для опытов используется набор SciFact: корпус научных аннотаций и утверждения с разметкой доказательств. Данные, веса моделей и обученная модель в Git не включены.

## Статус и ключевой результат

Проект завершён как воспроизводимый исследовательский прототип: реализованы
загрузка данных, три варианта поиска, два способа выбора доказательств,
дообучение проверяющей модели, end-to-end оценка, CLI, Streamlit-демо и FastAPI.

Лучший полный конвейер достиг `Macro-F1 0,7834` и `accuracy 0,8085` на 188
проверочных утверждениях SciFact. Это оценка качества на фиксированном корпусе,
а не универсальная проверка истинности произвольного научного текста.

## Установка и данные

Требуется Python от 3.10 до 3.12. Установка зависимостей и загрузка данных:

```text
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -e .
python scripts/download_data.py
```

Скрипт сохраняет набор SciFact в `data/scifact/`. Сначала он обращается к библиотеке `datasets` и набору `allenai/scifact`; если загрузчик набора недоступен, скрипт загружает архив SciFact и преобразует исходные файлы. Каталог `data/` исключён из Git.

При первом запуске также загружаются предварительно обученные модели. Для обучения проверяющей модели нужен доступ в сеть и достаточно места под её веса.

## Поиск публикаций

Для каждого утверждения ранжируются публикации по объединённому тексту заголовка и аннотации. Проверка выполнена на одних и тех же 188 утверждениях проверочной части, имеющих размеченные документы. Полнота показывает долю утверждений, для которых хотя бы один размеченный документ попал в первые `k` результатов. Средний обратный ранг оценивает позицию первого подходящего документа; при расчёте учитываются первые десять результатов.

| Способ поиска | Полнота@5 | Полнота@10 | Средний обратный ранг |
| --- | ---: | ---: | ---: |
| BM25 | 0,9043 | 0,9309 | 0,7822 |
| Векторный поиск | 0,8777 | 0,9202 | 0,7314 |
| Объединение рангов | 0,9096 | 0,9574 | 0,7925 |

Векторный способ использует `sentence-transformers/all-MiniLM-L6-v2`: все аннотации кодируются один раз, затем утверждение сравнивается с ними по косинусной близости. Дополнительного обучения на SciFact нет.

Объединение рангов рассчитывается методом взаимных обратных рангов: BM25 и векторный поиск независимо возвращают по 100 кандидатов, затем ранги складываются по формуле `1 / (60 + ранг)`. Такое объединение не смешивает исходные оценки с разными шкалами. На этой проверочной части оно подняло полноту@10 с 0,9309 до 0,9574 относительно BM25.

В пяти разобранных случаях объединение рангов подняло размеченную публикацию в первые десять результатов, хотя BM25 не нашёл её в своей десятке. Среди примеров — работа об изменении иммунного ответа при эпигенетическом воздействии на опухоль (место 3), работа о гликолизе в аксонах (место 9) и исследование витамина Е и риска рака простаты (место 3). Эти примеры показывают, что второй способ поиска может вернуть публикации, пропущенные BM25.

Запуск оценок:

```text
python scripts/evaluate_retrieval.py
python scripts/evaluate_dense_retrieval.py
python scripts/evaluate_hybrid_retrieval.py
```

## Выбор предложений с доказательствами

Здесь использован режим правильного документа: модели заранее передаётся публикация с размеченным доказательством. Так ошибка поиска публикаций не влияет на оценку выбора предложения. Результаты усреднены по 209 парам «утверждение — публикация» из тех же 188 проверочных утверждений. Для пары объединены все размеченные предложения. Точность, полнота и F1 при отсечении `k` считаются по первым `k` предложениям.

| Способ выбора | Точность@1 | Полнота@1 | F1@1 | Точность@3 | Полнота@3 | F1@3 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Независимые векторы | 0,5550 | 0,3925 | 0,4361 | 0,3477 | 0,6608 | 0,4292 |
| Совместная оценка пары | 0,6507 | 0,4631 | 0,5146 | 0,3860 | 0,7393 | 0,4793 |

Первый способ кодирует утверждение и предложение независимо моделью `sentence-transformers/all-MiniLM-L6-v2`. Второй оценивает их вместе моделью `cross-encoder/ms-marco-MiniLM-L-6-v2`. Обе модели использованы без обучения на SciFact. Совместная оценка улучшила все приведённые показатели; при выборе трёх предложений точность остаётся невысокой — 0,3860. Поэтому в итоговую проверку могут попасть нерелевантные предложения.

Качественная проверка показала исправления для утверждений об ADAR1 и расщеплении микроРНК белком Dicer, об ухудшении зрения у пожилых людей и о связи ингибиторов АПФ с нарушением функции почек: в первых трёх предложениях совместная модель находила больше размеченных доказательств, чем независимые векторы.

Запуск:

```text
python scripts/evaluate_evidence_selection.py
python scripts/evaluate_cross_encoder_evidence.py
```

## Определение вердикта

Проверяющая модель получает утверждение и размеченные доказательные предложения. Сначала оценивалась предварительно обученная модель `cross-encoder/nli-deberta-v3-xsmall`, затем та же основа дообучалась на SciFact.

| Вариант | Точность | Макро-F1 |
| --- | ---: | ---: |
| Без дообучения | 0,7447 | 0,7405 |
| Дообучение на SciFact | 0,8777 | 0,8633 |

Оценка выполнена в режиме правильных доказательств на 188 проверочных утверждениях. У модели только два класса: поддержки и противоречия. В исходной разметке SciFact нет отдельного класса «недостаточно сведений» для этой задачи. Поэтому утверждения без размеченного доказательства исключены, а отсутствие найденного доказательства в полном конвейере не следует трактовать как третий обученный класс.

Для исходной модели матрица ошибок показывает, что 42 утверждения с поддерживающим доказательством ошибочно получили противоположный вердикт. После дообучения таких ошибок осталось 11. Дообучение проведено на 505 утверждениях обучающей части; 188 проверочных утверждений использовались только для выбора лучшей эпохи. Обучение минимизирует перекрёстную энтропию, контрольная метрика — макро-F1. Проверены три эпохи, лучший результат получен после первой. Матрица ошибок лучшей модели:

| Истинная разметка / ответ модели | Поддержка | Противоречие |
| --- | ---: | ---: |
| Поддержка | 113 | 11 |
| Противоречие | 12 | 52 |

Обученная модель сохраняется локально в `checkpoints/verifier/`; эта папка исключена из Git. Воспроизведение обучения и проверка на размеченных предложениях:

```text
python scripts/train_verifier.py
python scripts/evaluate_claim_verification.py --model checkpoints/verifier
```

## Полный конвейер

Класс `ScientificClaimVerifier` объединяет поиск BM25 и векторный поиск, выбор предложений совместной моделью и дообученную проверяющую модель. Для одного утверждения находятся десять публикаций; из их аннотаций выбираются три наиболее подходящих предложения. Итог содержит вердикт, уверенность, предложения и источники.

Сравнение на тех же 188 проверочных утверждениях:

| Доказательства для проверяющей модели | Макро-F1 | Точность |
| --- | ---: | ---: |
| Размеченные вручную | 0,8633 | 0,8777 |
| Найденные конвейером | 0,7834 | 0,8085 |

С предсказанными доказательствами макро-F1 снизился на 0,0799. Это показывает влияние ошибок поиска документов и выбора предложений на финальный вердикт. Если подходящих предложений совсем нет, конвейер возвращает «недостаточно сведений». Это правило обработки пустого результата, а не отдельный класс, которому обучалась модель. Уверенность — вероятность выбранного класса после нормализации оценок модели; калибровка уверенности не проводилась.

```text
python scripts/evaluate_pipeline.py
python scripts/run_pipeline.py "Витамин D снижает риск респираторных инфекций"
```

## Демонстрация и служба запросов

Перед запуском нужны данные и обученная модель. Для интерактивной демонстрации:

```text
streamlit run app.py
```

Для службы запросов через веб-интерфейс:

```text
uvicorn api:app --host 0.0.0.0 --port 8000
```

Проверка готовности доступна по адресу `/health`, проверка утверждения — запросом `POST /verify` с полем `claim`. Ответ включает вердикт, уверенность, предложения-доказательства, названия публикаций и оценки ранжирования.

В образ контейнера входят корпус и локальная обученная модель. После подготовки данных и весов его можно собрать и запустить так:

```text
docker build -t scientific-claim-verifier .
docker run -p 8000:8000 scientific-claim-verifier
```

Сборку и запуск контейнера в нашей среде проверить не удалось: там не установлен Docker. Сам веб-службу проверили локально: она загрузила модели и корпус, ответила на запрос проверки утверждения и вернула вердикт вместе с предложениями и источниками.

## Тесты

Лёгкие unit-тесты не загружают нейросетевые веса и проверяют BM25 retrieval и
подготовку oracle-примеров SciFact:

```text
pip install -e ".[test]"
pytest -q
```

Полные evaluation-скрипты остаются интеграционной проверкой, поскольку требуют
локального корпуса, Hugging Face моделей и checkpoint проверяющей модели.

## Ограничения

- Оценки получены на одном проверочном разбиении SciFact; они не гарантируют такое же качество на другой научной области.
- Поиск и выбор предложений измеряют попадание в размеченные публикации и предложения, но не полноту научного обзора.
- Модель выбора предложений обучалась на задаче оценки релевантности, а не на разметке доказательств SciFact.
- Проверяющая модель обучена только на паре классов поддержки и противоречия; обработка пустого результата не заменяет обучение на примерах «недостаточно сведений».
- Уверенность модели не калибрована и не является вероятностью истинности научного утверждения.
- Результат зависит от загруженного корпуса и сохранённых весов моделей.
